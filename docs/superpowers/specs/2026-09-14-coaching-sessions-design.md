# Коучинговые сессии в miru — дизайн

Дата: 2026-09-14
Статус: согласован в чате, ждёт ревью файла

## Зачем

miru сейчас работает только для терапии: человек записывает встречу с терапевтом,
получает разбор, задания, темы к следующей встрече и паттерны по всей истории.
Та же схема подходит клиенту коуча. Цель — чтобы человек мог записывать и
терапевтические, и коучинговые встречи в одном аккаунте, и для коучинга получал
разбор, построенный вокруг целей.

## Решения, принятые в обсуждении

| Вопрос | Решение |
|---|---|
| Кто пользователь | Клиент коуча — тот же человек, что записывает свои сессии. Не коуч и не общий кабинет коуча с клиентом. |
| Где выбирается тип | У каждой сессии, перед записью. |
| Паттерны | Общие по всем сессиям, с поиском связей между терапией и коучингом. |
| Темы к следующей встрече | Раздельные по типу. |
| Что в разборе коучинга | Цели, шаги со сроками, препятствия, инсайты (все четыре). |
| Как хранить цели | Вариант A: внутри разбора, без отдельной таблицы целей. |

Отвергнуто:
- **B — отдельный трекер целей** (таблица, статусы вручную, шаги привязаны к целям).
  Примерно втрое больше работы. Может быть построен поверх A позже: поле типа и
  формат разбора не меняются.
- **C — только другой промпт.** Без переноса целей между сессиями теряется главное
  в коучинге.

## Не входит в эту работу

- Ручное управление целями (отметить достигнутой, переименовать, удалить).
- Пересчёт сроков («до пятницы») в даты и напоминания.
- Кабинет коуча, несколько клиентов, общий доступ.
- Выбор типа на уровне аккаунта или отдельный сайт для коучинга.

## 1. Данные

Миграция `supabase/migrations/023_session_kind.sql`, запускается вручную в Supabase:

- `sessions.kind text NOT NULL DEFAULT 'therapy' CHECK (kind IN ('therapy', 'coaching'))`.
  Существующие строки получают `'therapy'` через значение по умолчанию.
- `next_session_topics.kind text NOT NULL DEFAULT 'therapy'` с той же проверкой.
  - Темы от ИИ получают тип своей сессии.
  - Ручные темы получают тип, выбранный на дашборде в момент добавления.
- `homework` не меняется: тип читается через `session_id`. Задания без сессии
  метки не получают.
- Отдельной таблицы целей нет. Цели лежат в `sessions.ai_analysis` (JSON) коучинговой сессии.

Код, читающий сессии и темы, считает отсутствующий или пустой `kind` терапией. Так
приложение работает и до применения миграции, по образцу `isMissingColumn` в `src/lib/api.js`.

## 2. Путь пользователя

1. На дашборде над кнопкой записи — переключатель **Therapy | Coaching**.
   Последний выбор запоминается в браузере.
2. Запись и транскрипция без изменений. При сохранении в сессию пишется `kind`.
3. Сессия через Recall-бота (Zoom/Meet) получает тип, выбранный при запуске бота.
4. На странице сессии тип можно сменить с подсказкой
   «после смены запустите Analyse заново». Старый разбор при смене не удаляется.
5. **Analyse** выбирает промпт по `kind`.
6. Шаги из коучингового разбора попадают в задания, темы — в темы с `kind = 'coaching'`,
   тем же механизмом, что сейчас создаёт задания и темы из терапевтического разбора
   (`src/lib/sessionHomework.js`, `src/lib/sessionTopics.js`).
7. На дашборде карточка **Current goals** из последней разобранной коучинговой сессии.

## 3. ИИ

### 3.1 Разбор коучинговой сессии

Новый промпт и JSON-схема рядом с существующими в `src/app/api/analyze/route.js`.
Терапевтический промпт не меняется. Роут получает `kind` и `previous_goals`.

Поля ответа:

- `topics_covered`: string[] — как у терапии
- `overview`: string[] — как у терапии
- `goals`: `{ goal, status, progress }[]`
  - `status` ∈ `new | in_progress | changed | achieved | dropped`
  - `progress` — одна фраза о том, что сказано на этой встрече
- `homework`: `{ task, due, context }[]` — договорённые шаги
  - `due` — срок так, как его назвали, или `null`
  - Поле называется `homework`, чтобы существующий код создания заданий работал без изменений.
- `obstacles`: `{ obstacle, context }[]`
- `insights`: string[] — осознания и сильные вопросы коуча
- `for_next_session`: string[] — как у терапии, чтобы темы создавались тем же кодом

Правила промпта:
- ответ на языке транскрипта (та же `languageDirective`);
- только то, что есть в транскрипте: пустой массив лучше общего совета;
- шаги — только реально договорённые, без придуманных;
- тон прямой, без давления;
- если на встрече всплывает тяжёлое (здоровье, кризис), ИИ бережно это отмечает
  и не ставит диагнозов.

### 3.2 Прошлые цели

Чистая функция в `src/lib/`, без обращения к базе, чтобы её можно было тестировать:

- На входе список сессий пользователя и текущая сессия.
- На выходе `goals` из последней по `created_at` сессии, которая:
  - раньше текущей;
  - имеет `kind = 'coaching'`;
  - не удалена;
  - имеет разбор, который читается как JSON и содержит `goals`.
- Если такой сессии нет, возвращается `[]`, и все цели считаются новыми.
- Цели со статусом `achieved` или `dropped` в промпт передаются: ИИ должен знать, что
  они закрыты. Но они не показываются в карточке Current goals.

### 3.3 Паттерны

`src/lib/patternsInput.js` и `src/app/api/patterns/route.js`:
- Каждая сессия во входных данных помечается `[Therapy]` или `[Coaching]`.
- Роль в промпте нейтральная: «reviewing someone's therapy and coaching sessions».
- Добавляется указание искать связи между двумя типами встреч.
- Формат ответа не меняется.

### 3.4 Чат

- Чат, привязанный к сессии, получает системный промпт по её типу. Для коучинга — про цели
  и шаги, а не про чувства.
- Общий чат без сессии получает нейтральный промпт вместо «AI therapy companion».
- В `src/lib/chatPresets.js` добавляются 2–3 коучинговые подсказки.

### 3.5 Стоимость

Прошлые цели добавляют к промпту несколько строк. На квоту в 400 минут это
заметно не влияет. Учёт расходов не меняется.

## 4. Интерфейс и тексты

**Нейтральные тексты:**
- `layout.js`, заголовок: «Miru — Therapy Journal» → «Miru — Session Journal».
- Страница входа: «Your private therapy companion» → «Your private companion for therapy and coaching».
- Остальные упоминания терапии в интерфейсе → нейтральные «session», «specialist».
- Терапевтический разбор сохраняет свои термины.

**Дашборд (`src/app/page.js`):**
- Переключатель Therapy | Coaching над кнопкой записи.
- Карточка Current goals: до 5 целей со статусом `new`, `in_progress` или `changed`, у каждой метка статуса.
  Карточки нет, если нет разобранной коучинговой сессии.
- Настроение до и после — для обоих типов.

**Сессии (`src/app/sessions/page.js`):**
- Метка Therapy / Coaching в списке.
- Коучинговый разбор в порядке: цели → шаги → препятствия → инсайты → темы.
  Разделы описываются так же, как терапевтические в `src/lib/analysisFormat.js`.
- Переключатель типа с подсказкой о повторном Analyse.

**Задания (`src/app/homework/page.js`):**
- Метка типа у заданий, привязанных к сессии.
- Срок (`due`) показывается рядом с шагом, если он есть.

**Темы (`src/components/NextSessionTopics.jsx`):**
- Вкладки Therapy / Coaching видят только те, у кого есть сессии обоих типов.
  Остальные видят один список.

Экран для телефона (`MobileGate`) не меняется.

## 5. Проверка

Автотесты (`tests/`, существующий раннер):
- выбор прошлых целей:
  - нет прошлой коучинговой сессии → `[]`;
  - последняя коучинговая сессия не разобрана → берётся предыдущая разобранная;
  - терапевтическая сессия между ними не считается;
  - удалённая сессия не считается;
  - битый JSON разбора → сессия пропускается;
- сессия без `kind` считается терапией;
- карточка Current goals скрывает `achieved` и `dropped`.

Вручную:
- до миграции приложение работает как сейчас;
- после миграции записать 2–3-минутную «коучинговую» встречу с целью и договорённостью,
  запустить Analyse, проверить четыре блока, задания и темы;
- записать вторую такую встречу и проверить, что статусы целей учитывают первую.

## 6. Порядок работы

После каждого шага приложение остаётся рабочим.

1. Коммит экрана для телефона и правки страницы входа (готово, не закоммичено).
2. Миграция 023 и поле `kind` в сохранении сессий и тем. Переключатель на дашборде.
3. Коучинговый промпт, выбор прошлых целей, тесты.
4. Интерфейс: разбор коучинга, метки, Current goals, вкладки тем, нейтральные тексты.
5. Паттерны и чат.
